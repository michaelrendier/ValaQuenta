The Long Path of a word

Each step of an ASS word fired on the last position: the positions visited, the collisions, the order, and the flip test. A picture shows a structure; it is not evidence that the structure means anything beyond its definition.

About this visual

What you are looking at. An ASS word as a path. Each step is a generator (ADD, SCALE or SIGN) fired on the previous position; the page draws the positions visited, starting from x₀, with each step as a hop. This is ASSWord.trajectory, collisions and would_collide.

How to read it. Pick a preset word or build one with the buttons. Switch between the chrono order (as fired) and the zeta order (steps sorted by |u| descending): the end element is the same only if the steps commute, and the two paths show it. A ringed position was visited twice. The list under the picture says which candidate next steps would land on a visited position.

What it shows. That the order of a word is part of its content: re-ordering the same three steps changes the path and the final point. Collisions are real: ADD(+1) then ADD(−1) returns to x₀; two SIGN(−1) steps return to x₀. The flip test is the Recamán rule: a candidate is refused if it lands on a position already visited.

What it does not show. Anything about Recamán's sequence beyond that borrowed test; and it does not draw the composite element, only the positions. The composite and its u are in the text.

Numbers to check. Preset 2 (SCALE 8, ADD 2, SIGN(−1)·SCALE ½) with x₀ = 1: chrono path 1 → 8 → 10 → −5; zeta path differs. Preset 1: collision (0, 2) at position 1.

Code and data. Everything shown is recomputed in the browser by ass.js (composition, inverse, commutator, word, fold, the Long Path and exact rational arithmetic) and compared with the numbers the Python engine produced (ass_data.js); the result is printed above. Light and dark follow the system.
