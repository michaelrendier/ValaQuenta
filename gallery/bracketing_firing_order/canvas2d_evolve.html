About this visual

What you are looking at. A sedenion as a 16-component vector on the axes e₀…e₁₅ (the î ĵ k̂ of sixteen dimensions), and what a plan does to it. The input is the vector you set; each panel is the vector after one more step fires, drawn as 16 bars (dashed outline: the previous panel). The last panel is the output. Ĥ_RB has the same shape: one 16-component σ_RB in, one 16-component sedenion out.

How to read it. Set the input (or pick a preset, including the σ_RB of the h_rb_hat engine). Choose up to four items from the library: the input itself, a basis unit, an editable-preset sedenion a₁…a₄, or the Ĥ_RB coupling element C. Pick a tab: A bracketing, B firing order, C firing order of brackets, D bracketing of firing orders, then a plan from its list. Switch the reading: operator multiplies the input by the items' left-multiplication matrices in firing order (each panel is the vector after one item fires); element multiplies the sedenions themselves, panel by panel in the order the products are computed.

What it shows. That under the operator reading the bracketing does nothing (matrices associate) and only the firing order moves the output, while under the element reading the bracketing moves it too, because the sedenion product is not associative. The table under the picture puts the input, the output and the change side by side for every component.

What it does not show. A quantum measurement, a physical evolution or a claim about what Ĥ_RB does with σ_RB: the Ĥ_RB leaf is lift B of the h_rb_hat engine (a definition chosen to be testable, status OPEN there). The element reading has no separate input; put the input in as an item (source x) to make it part of the product.

Numbers to check. n = 3, input e₁ + e₁₀, plan ((A B | 2 1) C | 2 1) with the engine's a₁, a₂, a₃ fires C, B, A; its operator output starts −7, 1, −28, 12, 30, … and its element value starts 2, 9, 13, 7, 13, …

Code and data. Everything shown is recomputed in the browser by bf.js (the sedenion product, the plans, the four orderings, both readings, exact counts with BigInt, set membership) and compared with the numbers the Python engine produced (bf_data.js); the result is printed above.
