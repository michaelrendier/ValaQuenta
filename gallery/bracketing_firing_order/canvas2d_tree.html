A plan as a tree

Leaves, brackets and the firing order on every bracket; click a bracket to change its order. A picture shows a structure; it is not evidence that the structure means anything beyond its definition.

← Bracketing and firing order gallery

About this visual

What you are looking at. One plan drawn as a tree. Leaves are the items, each bracket is one operation, and the small numbered badge on a branch says when that child fires inside its bracket (1 first).

How to read it. Pick the items' order (a firing order of the leaves), the shape (flat, or one of the binary groupings of the fired sequence) and click a bracket to change its order: a binary bracket swaps, a flat bracket steps through all n! orders. The page says which kind the plan is: A, B, C or D, or a mixture. Both readings' outputs are drawn on the right.

What it shows. That the four kinds are four different choices on one object: A changes only the grouping, B only the order inside one bracket, C the orders on a fixed grouping, D the order of the leaves before the grouping (so it can group items that were not neighbours, as in ((A C) B)).

What it does not show. That the tree is a geometry of the sedenion. It is the structure of the plan; the sedenion vectors appear only in the output panels.

Numbers to check. ((A B | 2 1) C | 2 1): bracket badges 2 1 inside and 2 1 outside, fire sequence C B A, kind C. Flat with order 3 1 2 is B.

Code and data. Everything shown is recomputed in the browser by bf.js (the sedenion product, the plans, the four orderings, both readings, exact counts with BigInt, set membership) and compared with the numbers the Python engine produced (bf_data.js); the result is printed above. Light and dark follow the system.
